# supabase folder - what is here and why

| File / folder | What it is | Needed? |
|---|---|---|
| `migrations/001 ... 021` | The database changes, in order. Each one is pasted once into a Supabase project (staging first, then live). | Yes - this is the real history of the database. |
| `schema.sql` | The original tables before migration 001. | Yes - the starting point for building a database from nothing. |
| `policies-temporary-open.sql` | The old open access rules that migration 001 replaces. | Only for rebuilding from nothing (tests do this). |
| `seed-staging.sql` | Test company TEST and test data for staging. | Staging / tests only. |
| `staging-security-bundle.sql`, `staging-terminal-bundle.sql` | Migrations 001-002 and 004-005 in one file for the staging project. Generated by `node tools/build-staging-bundle.js`; a test fails if they are out of date. Never paste on live. | Staging only. |
| `maintenance/relink_punch_photos.sql` | One-off script that re-linked punch photos. | Delete once it is confirmed it was run. |

## Building a database from nothing (this is what the tests do)
1. `schema.sql`
2. `policies-temporary-open.sql`
3. `seed-staging.sql` (staging only)
4. `migrations/001` to `021`, in number order

## Notes
- The live project was moved over from an older setup; the live cut-over scripts were used once and have been removed.
- Tables of other apps on the live project sit in the hidden schema `archive_other_apps`. Dropping it is the owner's decision.
